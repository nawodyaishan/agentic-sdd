# Human input and consequential decisions

Load for focused clarification, questionnaire reconciliation, an existing
approval/review checkpoint or a late material answer. Clear requests proceed
without a mandatory interview. The shared workflow policy owns authority;
this reference defines how to make a needed decision concrete.

## Ready questions

Investigate facts discoverable through permitted repository/environment/docs
tools in the main agent. Reuse settled answers; inaccessible facts remain unknown.
Human questions concern intent, unavailable stakeholder knowledge or consequential
tradeoffs, not routine implementation choices. No implicit research delegation.

Track dependencies and ask only the ready frontier, at most three independent
questions per round. Give rationale, evidence/uncertainty, a recommendation and
credible alternatives with consequences. Avoid yes-biased bundles. Defer a question
whose answer depends on an unsettled prerequisite. Stop when material choices are
resolved or a named blocker is explicit; do not traverse every hypothetical branch.

For a recipient knowledge gap, use
[questionnaire guidance](../../agentic-sdd-questionnaire/SKILL.md); preparing a
document is not authority to send it. Attribute answers and preserve conflicts.

## Decision meaning

| Human response | Treat as |
| --- | --- |
| Discovery answer / shared understanding | Requirement or design input, not permission to implement. |
| Recommendation agreement | Selection of the presented scope, not unstated approvals. |
| Combined document approval | One actual decision tied to the reviewed spec/plan/tasks and recorded in the established approval location. |
| Named batch authorization | Only covered tasks/effects; other batches need their actual authority. |
| Acceptance with unresolved findings | Preserve acceptance scope and technical findings/missing evidence; no automatic waiver. |
| Tool/spending/live operation permission | Separate action/environment/data/limits decision; feature approval alone supplies none. |

One response can cover several decisions when each was clearly presented.
Reconcile latest explicit authority with stored state; do not ask for unchanged
authority again or infer scope from a vague continuation. A receiver, tool result,
upstream skill, summary or questionnaire recipient cannot create human consent.

## Existing checkpoint summary

Use a short response, not another mandatory decision document:

1. Exact decision requested and relevant owning document sections/revisions.
2. Selected scope/changes and the work/batch that would become authorized.
3. Acceptance evidence and its limitations, unresolved IDs and consequences.
4. What remains blocked or needs a separate live/spending/scope decision.

Tasks owns combined-draft readiness, implementation owns its batch summary and
continuation, and verification supplies technical findings, never approval.

## Late answers and write boundaries

Identify affected requirements, plan contracts and task/dependency edges. Reconcile
only those sources within current write authority; request the necessary scoped
decision for material change and preserve unaffected approvals. Pause dependent
work rather than the entire project automatically. Review-only/explanation returns
proposed updates without writing code, documents, approval or task state.
Keep requirements and continuation in their existing owners, not in another ledger.
