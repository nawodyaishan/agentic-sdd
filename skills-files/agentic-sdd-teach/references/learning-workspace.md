# Optional persistent learning workspace

Use only after the user selects this branch and its workspace/effects. These
formats adapt inspected Matt Pocock mission/resource/learning-record principles;
they are not dependencies on external template files or a required course layout.

## Mission

Keep a short `MISSION.md` or an existing equivalent: concrete reason/goal,
observable success, relevant time/budget/prior-knowledge constraints and out-of-scope
topics. Reuse known intent. Ask only consequential missing information; obtain
confirmation before changing the mission rather than inferring it from a lesson.

## Resources and reference

Use an existing source list or create `RESOURCES.md` only when it serves repeated
learning. Annotate primary/high-trust sources with what they cover and when useful.
Separate knowledge references from optional communities, respect stated community
preferences and show gaps. Discovery does not authorize contacting anyone.
Use existing glossary terms; create compact references/HTML only within requested
artifact scope. Preserve good material and explain consequential pruning.

## Lessons and learning records

Create short lessons around one tangible goal and a feedback loop. Reuse existing
assets when present; do not create a shared asset framework before a need exists.
Avoid adding mission/resource/notes files merely to fill a prescribed scaffold.

When authorized, add a concise learning record for demonstrated understanding,
an attributed prior-knowledge claim, a corrected misconception or an agreed mission
change. Existing numbering wins; otherwise choose the next unused `0001-topic.md`
in `learning-records/`. Create directories lazily and never overwrite a record.
Suggested content: what was established, its evidence/confidence and implications.
Mark contradictions/supersession explicitly; coverage or a session activity log
does not establish learning. Keep credentials/private data out of learning assets.
