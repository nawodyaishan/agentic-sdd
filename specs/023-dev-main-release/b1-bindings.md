**Permissions/rules inventory (T2).** For `dev`, allow only the owner to bypass the PR requirement for direct updates; a bypass on the operation does not demonstrate who authored or last updated a PR. Contributor PRs require an explicit owner review on the current head. For `main`, keep PR, current trusted admission result and immutable history mandatory even for the owner. Restrict updates/merges to owner; no global admin bypass. For `v*`, separate restrict-creation (sole owner) from no-bypass update/deletion. Effective actor lists, stale-review invalidation and actual ref/ruleset layering require hosted evidence, not YAML. A protected `release` environment remains necessary for the tooling pin and tap credential even after removing the manual click.

**Git fixture (executed, isolated temp repo).** Base `ec3e6f3` has `release-version=v0.9.0`; `dev` at `df174b8` changes it to `v0.10.0`. A `--no-ff` promotion at `e4914d1` has those two parents in order, shares tree `7e7849e` with `dev`, and reads `v0.10.0` from that commit. Annotated tag object `d39291e` peels to the merge. A same-named branch `refs/heads/v0.10.0` also resolves to the merge. **Short ref + SHA cannot distinguish these events.** This experiment proves git properties, not GitHub identity, ref protection or the hosted check result.
