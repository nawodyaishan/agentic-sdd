# Homebrew package publishing

## Outcome and sources

Let users install `agentic-sdd` with `brew install nawodyaishan/tap/agentic-sdd` and get a working, self-contained binary — no repo clone required — that stays current via `brew upgrade` on every tagged release. This feature directly mirrors the finely-working, already-shipping release pipeline in `/Users/nawodyaishan/Documents/GitHub/quiz-snap`, not a redesign: `.goreleaser.yml`, `.github/workflows/release.yml`, `.github/workflows/ci.yml`, `Makefile` (`verify`/`build-darwin`/`tag`/`release` targets), and `internal/version/version.go` are the reference implementation to port, adapted only where agentic-sdd's actual code differs (no cobra — this repo's `AGENTS.md` mandates stdlib `flag` and small explicit functions; no macOS TCC-permission caveats — agentic-sdd has no screen-capture/Accessibility dependency; no golangci-lint config currently in this repo). Other sources: `AGENTS.md` (Go layout, Safe changes, Verification, SDD feature conventions), `README.md` (Get started, CLI reference), `internal/skillsync/sync.go` (`Sync(repo, home, apply, out)` reads `<repo>/skills-files`), `cmd/agentic-sdd/main.go` (current stdlib-flag command surface, no version command). This repository has no top-level product SRS or roadmap (see `specs/001-cli-quality/spec.md`).

Reference details confirmed from quiz-snap (read directly) plus Context7 `/goreleaser/goreleaser` and web search (current as of 2026-09): the action-scoped `GITHUB_TOKEN` cannot write to a different repository ("resource not accessible by integration"), so `brews:` publishing needs a separate PAT (`HOMEBREW_TAP_TOKEN`) scoped to the tap repo's contents, passed as a distinct env var to `goreleaser-action`; `actions/checkout` needs `fetch-depth: 0`.

**Tap repository: reuse `nawodyaishan/homebrew-tap`**, the same tap quiz-snap already publishes to (GoReleaser's `brews:` supports multiple formulas in one tap via separate `Formula/*.rb` files — quiz-snap's own `.goreleaser.yml` already points at `repository.name: homebrew-tap`, not a per-project tap). This resolves the earlier "tap doesn't exist yet" open question if that repo already exists for quiz-snap; still confirm the repo exists and `HOMEBREW_TAP_TOKEN` is valid for it before relying on it (Acceptance criterion 6).

## Scope

- Port `internal/version` from quiz-snap verbatim in shape (`Version = "dev"`, `Commit = "none"`, `Date = "unknown"`, `GoVersion = "unknown"`, same doc comment convention), values injected by GoReleaser `ldflags` at release build time.
- Add a `version` command to `cmd/agentic-sdd`'s existing stdlib-`flag` command switch (alongside `preview`/`apply`/`help`), printing the same four lines quiz-snap's `internal/cli/version.go` prints (`agentic-sdd <version>`, `commit:`, `date:`, `go version:`) — adapted to this repo's flag-based dispatch, not cobra. Extend `main_test.go` accordingly.
- Embed `skills-files/` into the binary via `go:embed` so a Homebrew-installed binary works with no repository checkout present — this has no quiz-snap equivalent (quiz-snap ships no runtime data files) and is the one necessary addition beyond a direct port. `--repo` continues to override the source directory for local development and CI/tests; when unset, `Sync` reads the embedded tree instead of defaulting to `.`.
- Add `.goreleaser.yml` at repo root, structurally identical to quiz-snap's: `before.hooks: [go mod tidy]`; `builds` for `cmd/agentic-sdd` targeting `darwin` only (`amd64`, `arm64` — matching quiz-snap's own darwin-only scoping, no Linux/Windows), `CGO_ENABLED=0`, `-trimpath`, `mod_timestamp: "{{ .CommitTimestamp }}"`, ldflags injecting the four `internal/version` fields plus `GOVERSION`; `universal_binaries` (`replace: true`) to merge amd64+arm64 into one lipo binary exactly like quiz-snap; `archives` (tar.gz, same name template); `checksum`; `changelog` (same `docs:`/`test:`/`ci:`/`chore:` exclusion filters); `brews:` block (`repository.owner: nawodyaishan`, `repository.name: homebrew-tap`, `repository.token: "{{ .Env.HOMEBREW_TAP_TOKEN }}"`, `directory: Formula`, `homepage`, `description`, `license: MIT`, `install`, `test` running `--help` and `version`) — no `caveats` block (nothing analogous to quiz-snap's TCC-permission checklist applies to this CLI).
- Add `.github/workflows/release.yml`, structurally identical to quiz-snap's: trigger on `push: tags: ["v*"]`; `permissions: contents: write, id-token: write`; job `environment: release`; steps — checkout (`fetch-depth: 0`), `actions/setup-go` (`go-version-file: go.mod`), a `Verify` step running this repo's equivalent local gate, a `Get Go version` step exporting `GOVERSION`, a `Validate Homebrew tap token` step (`gh api repos/nawodyaishan/homebrew-tap --jq .default_branch` using `HOMEBREW_TAP_TOKEN`) that fails fast before any build work if the tap token or repo is misconfigured, then `goreleaser/goreleaser-action` (`args: release --clean`) with `GITHUB_TOKEN`, `HOMEBREW_TAP_TOKEN`, `GOVERSION` env.
- Add `Makefile` targets mirroring quiz-snap's naming and behavior, adapted to this repo's existing targets (`preview`/`apply`/`test`/`vet`/`docker-e2e`/`hooks-install` stay unchanged): `mod-verify` (`go mod verify`), `tidy-check` (`go mod tidy` + `git diff --exit-code -- go.mod go.sum`), `build` (current-OS binary), `build-darwin` (cross-compile amd64+arm64 into `bin/`), `verify` (`mod-verify tidy-check vet test build-darwin` — the target the release workflow's `Verify` step runs, matching quiz-snap's `verify` composition minus `lint`, since this repo has no golangci-lint config), `tag` (`V=`/`MSG=` annotated tag helper), `release` (`goreleaser release --snapshot --clean` local dry run, with `GOVERSION` exported the same way quiz-snap's `make release` does).
- Optionally add `.github/workflows/ci.yml` mirroring quiz-snap's quality gate shape (`push`/`pull_request` on non-tag changes, `make mod-verify`, `make vet`, `make test`, `make build-darwin`) so ordinary PRs get the same checks the release workflow's `Verify` step runs — quiz-snap runs this on `ubuntu-latest` even though it's darwin-only, since the checked steps don't call platform-specific binaries at compile time; same reasoning applies here. No `golangci-lint` step, since this repo has no lint config (unlike quiz-snap) — do not add one as a side effect of this feature.
- Update `README.md` with the `brew install nawodyaishan/tap/agentic-sdd` path and a maintainer release note (`make tag V=vX.Y.Z MSG="..."` then `git push origin vX.Y.Z`), matching quiz-snap's documented flow. Add a pointer in `AGENTS.md`'s "SDD feature conventions" section to the release/publish mechanism.
- Document, as a manual prerequisite (not part of this feature's automation), confirming `nawodyaishan/homebrew-tap` exists and is reachable, and that `HOMEBREW_TAP_TOKEN` is set as a repository (or `release`-environment) secret on this repo with write access to it.

## Safety and compatibility

- No change to `Sync`'s safety contract (staged install, backup-before-replace, symlink/special-file refusal, rollback) — only its default source filesystem changes from an on-disk path to an embedded one when `--repo` is unset.
- Existing `go run ./cmd/agentic-sdd preview|apply`, `make preview`/`make apply`, and explicit `--repo .` from a checkout keep working unchanged (embedding is additive).
- The release workflow only builds, tests, and publishes release artifacts and the tap formula; it never runs `apply` against any real user home, matching quiz-snap's own boundary.
- `HOMEBREW_TAP_TOKEN` is a secret scoped to `Contents: Read and write` on the tap repo only, stored as a GitHub Actions secret (optionally under a `release` environment, matching quiz-snap), never printed or logged.

## Acceptance

1. `go build ./cmd/agentic-sdd` and running the resulting binary's `preview`/`apply` from an arbitrary working directory (no `skills-files/` present) list/install skills correctly, sourced from the embedded tree.
2. `agentic-sdd version` prints a version string; when built via `goreleaser build --snapshot --clean` (or `make release`) it reflects the injected version/commit/date/go-version, not the `dev`/`none`/`unknown` defaults.
3. `goreleaser check` validates `.goreleaser.yml`; `make release` (`goreleaser release --snapshot --clean`) locally produces darwin archives (one universal binary per architecture pairing, per `universal_binaries`) and a `Formula/agentic-sdd.rb` under `dist/homebrew/Formula/` with correct `url`, `sha256`, `install`, and `test` blocks, without requiring network publish.
4. `make verify` (`mod-verify tidy-check vet test build-darwin`) passes locally and is what `.github/workflows/release.yml`'s `Verify` step runs.
5. The `Validate Homebrew tap token` step's command (`gh api repos/nawodyaishan/homebrew-tap --jq .default_branch`) succeeds when run manually with a valid `HOMEBREW_TAP_TOKEN` against the real tap repo (verified as part of the manual prerequisite, not by the agent — see Outside scope).
6. `README.md` documents the `brew install` path and the `make tag`/`git push origin vX.Y.Z` release process; `AGENTS.md` gains a pointer to the release/publish workflow.

## Outside scope

Confirming `nawodyaishan/homebrew-tap` actually exists and is reachable, generating/rotating the real `HOMEBREW_TAP_TOKEN` PAT and storing it as a secret, pushing the first real `v*` tag, and any live `brew install`/`brew upgrade` verification against the real tap — these are manual, credentialed, live-system actions requiring separate human execution and authorization, not implementable or verifiable by an agent in this workspace. Linux/Windows builds (out of scope — direct port keeps quiz-snap's darwin-only scoping). Homebrew Cask support, other package managers (apt, scoop, nix), semantic-release/automated version bumping, and adding golangci-lint (quiz-snap has it; this repo currently doesn't, and adding a linter is a separate concern from mirroring the publish pipeline).
